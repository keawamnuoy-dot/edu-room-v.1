# EduRoom — ระบบจองห้องประชุม คณะครุศาสตร์

เว็บแอปจองห้องประชุมสำหรับคณะครุศาสตร์ มหาวิทยาลัยราชภัฏเชียงราย ใช้ PHP/PDO, MariaDB และ JavaScript โดยข้อมูลบัญชี ห้อง และการจองเก็บในฐานข้อมูล `bookking_name` ส่วนการยืนยันตัวตนและตรวจสิทธิ์ทำบนเซิร์ฟเวอร์

ดู [Flowchart การใช้งานระบบ (PDF)](./FLOWCHART.pdf) หรือเปิด [ไฟล์ต้นฉบับสำหรับพิมพ์](./tools/flowchart-print.html) สำหรับลำดับการจอง การอนุมัติ และการเตรียมห้อง

ตราสัญลักษณ์คณะครุศาสตร์ที่หน้าเข้าสู่ระบบและแถบเมนูใช้ไฟล์ใน `assets/crru-education-emblem.jpg` ซึ่งดาวน์โหลดจากเว็บไซต์คณะเพื่อให้ระบบแสดงผลจากเซิร์ฟเวอร์ภายใน

## ติดตั้งบน XAMPP

1. เริ่ม Apache และ MySQL ใน XAMPP แล้วตรวจว่าใช้ฐานข้อมูล `bookking_name` ที่ถูกต้อง
2. สร้างตารางโดยไม่ลบฐานข้อมูลหรือตารางเดิม:

   ```powershell
   Get-Content -Raw C:\xampp\htdocs\bookmain\api\schema.sql | & C:\xampp\mysql\bin\mysql.exe -uroot
   ```

   ไฟล์ schema ใช้ `CREATE TABLE IF NOT EXISTS` และ `USE bookking_name`; ไม่มีคำสั่ง DROP. การตั้งค่าเชื่อมต่ออยู่ใน `api/config.php` (ค่า XAMPP เริ่มต้น: `root` ไม่มีรหัสผ่าน)
3. สร้าง Super Admin คนแรกด้วยคำสั่งใน PowerShell แล้วกรอกรหัสผ่านเมื่อระบบถาม:

   ```powershell
   & C:\xampp\php\php.exe C:\xampp\htdocs\bookmain\tools\create-account.php admin@crru.ac.th "ผู้ดูแลระบบ" super_admin
   ```

   ใช้คำสั่งเดียวกันเพิ่มบัญชี `admin`, `staff` หรือ `user` โดยระบุบทบาทตามต้องการ ผู้ดูแล Super Admin สามารถจัดการบทบาทและสถานะบัญชีภายในระบบได้ ไม่สามารถกำหนดสิทธิ์จากแบบฟอร์มสมัครสมาชิกหรือข้อมูลนำเข้า
4. สำหรับฐานข้อมูลที่ติดตั้งไว้ก่อนมีข้อมูลสมาชิก ให้รัน migration เพิ่มคำนำหน้า สถานภาพ และรูปโปรไฟล์:

   ```powershell
   Get-Content -Raw C:\xampp\htdocs\bookmain\api\migrations\20261020_member-profile.sql | & C:\xampp\mysql\bin\mysql.exe -uroot
   ```

5. เปิด `http://localhost/bookmain/` ผ่าน XAMPP (ไม่เปิด `index.html` โดยตรง) แล้วเข้าสู่ระบบ บัญชีใหม่สมัครได้ด้วยอีเมล `@crru.ac.th`; ทุกบัญชีที่สมัครได้รับบทบาท User เท่านั้น และต้องแนบรูปโปรไฟล์ JPG, PNG หรือ WebP ขนาดไม่เกิน 2 MB พร้อมเลือกคำนำหน้าและสถานภาพ

## ย้ายข้อมูลเดิมจาก localStorage

การย้ายทำได้ครั้งเดียวจากเบราว์เซอร์/โปรไฟล์เดิมที่มีข้อมูล `eduroom-crru-v1` และ `eduroom-demo-accounts`:

1. สำรองข้อมูลเดิมของเบราว์เซอร์ไว้ก่อน และเข้าสู่ระบบ Super Admin ที่สร้างไว้
2. เปิดเมนูบัญชีผู้ใช้ แล้วเลือก **นำเข้าข้อมูลเดิมจากเบราว์เซอร์** และยืนยัน
3. ระบบนำเข้าห้อง การจอง นโยบาย การแจ้งเตือน และบัญชีสมาชิกเดิมลง MySQL ใน transaction หลังนำเข้าสำเร็จจะลบคีย์ข้อมูลแอปและบัญชีรหัสผ่านเดิมออกจาก localStorage ของเบราว์เซอร์นั้น

รหัสผ่านสมาชิกเดิมถูกแฮชด้วย `password_hash()` ก่อนบันทึก และทุกบัญชีที่นำเข้าจะเป็น `user` เสมอ โดยไม่เชื่อถือค่า role ใน localStorage. บัญชีทดลองเดิมที่เป็นบทบาท Admin/Staff/Super Admin ไม่ได้ถูกสร้างเป็นบัญชีจริงโดยอัตโนมัติ ให้ผู้ดูแลระบบสร้างบัญชีที่ได้รับอนุญาตด้วยคำสั่ง CLI. API ปฏิเสธการนำเข้าซ้ำ และปฏิเสธการเขียนทับข้อมูลแอปที่อยู่ในฐานข้อมูลแล้ว

## บทบาท

| บทบาท | สิทธิ์หลัก |
|---|---|
| **Super Admin** | ทุกหน้าและการจัดการระบบ รวมถึงจัดการสมาชิกทั้งหมด เปลี่ยนบทบาท/สถานะบัญชี นโยบาย และการนำเข้าครั้งเดียว |
| **Admin** | จัดการห้อง อนุมัติ/ไม่อนุมัติคำขอ และเพิ่มบัญชี User, Staff หรือ Admin |
| **Staff** | ดูรายการที่อนุมัติและอัปเดตขั้นตอนเตรียมห้อง |
| **User** | ดูห้อง/ปฏิทิน และจัดการคำขอจองของตนเอง |

API ตรวจสิทธิ์ซ้ำจาก role ในฐานข้อมูล และตรวจการเปลี่ยนแปลงข้อมูลตามบทบาท ไม่เชื่อถือ role ที่ส่งจากเบราว์เซอร์ ใช้ PHP session cookie แบบ HttpOnly/SameSite และ CSRF token; ห้องและการจองเก็บในตารางสัมพันธ์แยกกัน (`rooms`, `bookings`) ส่วนบัญชีอยู่ใน `users`.

เมนู **จัดการสมาชิกทั้งหมด** ให้ Admin เพิ่มบัญชี User, Staff หรือ Admin ได้เท่านั้น โดยไม่แสดงหรืออนุญาตให้แก้ไขบัญชีเดิม และไม่สามารถสร้าง Super Admin ได้ ส่วน Super Admin สามารถค้นหาและกรองสมาชิก แก้คำนำหน้า ชื่อ สถานะสมาชิก อีเมลสำหรับเข้าสู่ระบบ หน่วยงาน เบอร์โทรศัพท์ และรูปโปรไฟล์ ตั้งรหัสผ่านใหม่ เปลี่ยนบทบาท หรือเปิด/ปิดบัญชีได้ สถานะสมาชิกมีตัวเลือก อาจารย์, เจ้าหน้าที่, นักศึกษา และบุคลากรภายนอก; สมาชิกเดิมที่ข้อมูลสถานะยังไม่ทราบจะไม่ถูกจัดประเภทให้อัตโนมัติและสามารถเลือกสถานะได้เมื่อแก้ไขข้อมูล การสร้างสมาชิกทั้งจาก Admin และการสมัครใหม่บังคับแนบรูปโปรไฟล์ JPG, PNG หรือ WebP ขนาดไม่เกิน 2 MB; API ตรวจชนิดไฟล์จริงและปฏิเสธคำขอที่ไม่มีรูปด้วย ผู้ดูแลแก้ไขข้อมูลส่วนตัวและรหัสผ่านของตนเองจากเมนูโปรไฟล์ โดยต้องยืนยันรหัสผ่านปัจจุบันก่อนบันทึก เซิร์ฟเวอร์ไม่อนุญาตให้แก้บทบาท/สถานะของบัญชีที่กำลังใช้งาน และป้องกันไม่ให้ปิดหรือลดสิทธิ์ Super Admin คนสุดท้ายที่ยังเปิดใช้งาน การเปลี่ยนอีเมล/ชื่อจะปรับข้อมูลเจ้าของรายการจองที่เก็บในฐานข้อมูลด้วย่ยวข้องด้วย รหัสผ่านเริ่มต้นที่กำหนดตอนสร้างบัญชีควรส่งให้สมาชิกผ่านช่องทางที่ปลอดภัย

เมนู **สรุปสถิติรายเดือน** แสดงเฉพาะ Super Admin เลือกเดือนเพื่อดูคำขอจองที่ช่วงวันใช้งานทับซ้อนกับเดือนนั้น สถานะการจอง ชั่วโมงและวัน-ห้องของรายการที่อนุมัติแล้ว จำนวนสมาชิกสมัครใหม่ และข้อมูลการใช้แยกตามห้อง ส่งออกข้อมูลได้เป็น CSV สำหรับเปิดในโปรแกรมตารางคำนวณ หรือใช้ **พิมพ์ / บันทึก PDF** เพื่อพิมพ์หรือบันทึกสำเนารายงานตามเดือนที่เลือก ชั่วโมงการใช้ห้องคำนวณจากช่วงเวลาที่จองซ้ำในแต่ละวันสำหรับรายการจองหลายวัน

ในหน้าคิวอนุมัติ Admin ต้องเลือก Staff ที่เปิดใช้งานก่อนอนุมัติ ระบบจึงจะส่งรายการจองเข้า queue ของ Staff คนนั้นเท่านั้น เจ้าหน้าที่ผู้รับงานกดรับงาน เริ่มจัดเตรียม และยืนยันเตรียมห้องเสร็จได้จากหน้า **เตรียมห้องประชุม** เมนูและหัวข้อ **งานที่ส่งต่อให้เจ้าหน้าที่** แสดงตัวเลขสีแดงตามจำนวนงานที่มอบหมายและยังเตรียมไม่เสร็จ ระบบตรวจคิวล่าสุดให้อัตโนมัติทุก 15 วินาที และยังสามารถโหลดงานล่าสุดได้ด้วย

เมื่อบันทึกคำร้องจองใหม่ ระบบส่งอีเมลแจ้งบัญชี Admin และ Super Admin ที่เปิดใช้งานด้วยข้อความ “ขณะนี้ มีการจองห้องเรียน ห้องประชุม ลานกิจกรรม ให้ท่านกลับไปที่ระบบการจองห้องประชุม เพื่ออนุมัติการจองห้อง” เมื่ออนุมัติและมอบหมาย Staff แล้ว ระบบส่งข้อความ “ขณะนี้ มีการอนุมัติห้องเรียน ห้องประชุม ลานกิจกรรม เรียบร้อยแล้ว ให้ท่านกลับไปที่ระบบการจองห้องประชุม เพื่อเตรียมห้องประชุม” ไปยังอีเมลของ Staff ที่ได้รับมอบหมายโดยตรง ระบบใช้ PHP `mail()` และค่าการเชื่อมต่อ SMTP ของ XAMPP; อีเมลที่ส่งไม่สำเร็จจะแสดงคำเตือนในระบบและบันทึกข้อผิดพลาดใน PHP error log

ยังไม่ได้เปิด SMTP relay ใน XAMPP โดยอัตโนมัติ ให้ขอ SMTP hostname, port, encryption mode, username, sender address และ App Password จากผู้ดูแลอีเมล CRRU ก่อน โดย SMTP hostname ต้องเป็น server name (เช่น `smtp.example.ac.th`) ไม่ใช่อีเมล username; ค่าที่ให้มาก่อนหน้านี้ `education@crru.ac.th` จึงยังไม่เพียงพอสำหรับตั้ง server

เมื่อได้รับข้อมูลครบแล้ว เปิด PowerShell แบบ Run as administrator และเรียกสคริปต์ตั้งค่าแบบโต้ตอบ:

```powershell
& C:\xampp\htdocs\bookmain\tools\configure-smtp.ps1
```

สคริปต์รับรหัสผ่านแบบซ่อนข้อความ สำรอง `php.ini` และ `sendmail.ini` ก่อนแก้ค่า กำหนด SMTP ผ่าน TLS (พอร์ต 587) หรือ SSL/TLS (พอร์ต 465) และไม่ทำงานต่อจนพิมพ์ `YES` ยืนยัน หากเขียนไฟล์ตั้งค่าไม่สำเร็จ สคริปต์จะพยายามคืนค่าเดิมจากไฟล์สำรอง รหัสผ่าน SMTP ถูกเก็บเป็นข้อความธรรมดาใน `C:\xampp\sendmail\sendmail.ini` ตามข้อจำกัดของ XAMPP sendmail จึงต้องจำกัดสิทธิ์เข้าถึงเครื่อง/ไฟล์และใช้ App Password ที่เพิกถอนได้ ห้าม commit หรือส่งไฟล์ตั้งค่านี้ต่อ หลังตั้งค่าสำเร็จให้ Restart Apache และส่งอีเมลทดสอบ ตรวจ `C:\xampp\sendmail\error.log` เมื่อมีปัญหา

## ความสามารถ

- หน้าแรกแสดงรายการจองทั้งหมดที่วันใช้งานทับซ้อนกับเดือนปัจจุบัน พร้อมห้อง ผู้จอง วันที่ เวลา จำนวนผู้เข้าร่วม วัตถุประสงค์ อุปกรณ์ หมายเหตุ และสถานะ โดยจำกัดข้อมูลตามสิทธิ์ของแต่ละบทบาท

- แค็ตตาล็อกห้อง ค้นหา จัดการห้อง/อุปกรณ์ และรูปภาพ
- คำขอจองแบบหลายวัน พร้อมวัตถุประสงค์ หมายเหตุ อุปกรณ์ และลายเซ็น
- ตรวจช่วงเวลาชนกัน รวมถึงบนเซิร์ฟเวอร์ก่อนบันทึกคำขอ
- อนุมัติ/ไม่อนุมัติพร้อมเหตุผล คิวเตรียมห้อง และปฏิทิน
- สมัครสมาชิกด้วยข้อมูลติดต่อและอีเมลมหาวิทยาลัย
- ธีมสีฟ้า–ขาว และการปรับขนาดตัวอักษร 100–130%

## ข้อควรระวังด้านความปลอดภัย

การตั้งค่านี้เหมาะสำหรับพัฒนาและใช้งานทดสอบบนเครื่องภายในเท่านั้น โดยเฉพาะค่า MariaDB `root` ที่ไม่มีรหัสผ่านเป็นค่าเริ่มต้น XAMPP: **ห้ามเปิด Apache, MariaDB หรือแอปนี้สู่อินเทอร์เน็ต/เครือข่ายสาธารณะ** ก่อนใช้งานจริงให้สร้างบัญชีฐานข้อมูลสิทธิ์จำกัด ตั้งรหัสผ่านที่แข็งแรงและแก้ `api/config.php`, ใช้ HTTPS, จำกัดการเข้าถึง Apache/ฐานข้อมูล, สำรองและทดสอบกู้คืนข้อมูล, เพิ่ม rate limiting/การตรวจสอบอีเมล/CSRF protection ที่เหมาะกับการ deploy และทบทวนมาตรการคุ้มครองข้อมูลส่วนบุคคลของมหาวิทยาลัย

การแจ้งเตือนอีเมลใช้ PHP `mail()` ผ่าน SMTP ที่ตั้งค่าในเครื่องเซิร์ฟเวอร์; หากไม่ได้กำหนด SMTP ที่ส่งออกได้ ระบบจะบันทึกคำร้อง/ผลอนุมัติตามปกติแต่แสดงคำเตือนเมื่อการส่งอีเมลล้มเหลว LINE ยังเป็นเพียงค่าตั้งค่าในแอปและยังไม่ได้ส่งข้อความจริง ปุ่มขนาดตัวอักษรยังบันทึกค่าความชอบใน localStorage แต่ข้อมูลผู้ใช้/ห้อง/การจองใช้ MySQL เป็นแหล่งข้อมูลหลัก
